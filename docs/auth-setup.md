# Auth setup (OAuth + sessions)

The web app uses **Auth.js (NextAuth v5)** with the Prisma adapter. Three providers
are available, each enabled only when its env vars are present:

- **GitHub** — `AUTH_GITHUB_ID`, `AUTH_GITHUB_SECRET`
- **Google** — `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET`
- **Email magic link** — `EMAIL_SERVER` (nodemailer SMTP URL) + `EMAIL_FROM`. Sends a
  verification link that confirms email ownership and signs the user in.
- **Dev email** (local only) — `AUTH_DEV_LOGIN=1` (no password; upserts a user)

### Email magic link (signup with verification)

Set an SMTP relay and a from-address:

```
EMAIL_SERVER=smtp://user:pass@smtp.host:587
EMAIL_FROM=TrustMCP <no-reply@your-domain>
```

The Prisma adapter stores the one-time token in `VerificationToken`; clicking the
emailed link verifies the address and creates/logs in the user. The same SMTP config
powers transactional emails (access-request and approval/deny notices).

Always set `AUTH_SECRET` (`openssl rand -base64 32`) and, in production behind a load
balancer, `AUTH_URL=https://your-domain` (the app sets `trustHost: true`).

## GitHub OAuth app

1. GitHub → Settings → Developer settings → **OAuth Apps** → New OAuth App.
2. Homepage URL: `https://your-domain`
3. **Authorization callback URL:** `https://your-domain/api/auth/callback/github`
   (local: `http://localhost:3000/api/auth/callback/github`)
4. Copy the Client ID/secret into `AUTH_GITHUB_ID` / `AUTH_GITHUB_SECRET`.

## Google OAuth client

1. Google Cloud Console → APIs & Services → **Credentials** → Create OAuth client ID →
   Web application.
2. **Authorized redirect URI:** `https://your-domain/api/auth/callback/google`
   (local: `http://localhost:3000/api/auth/callback/google`)
3. Copy into `AUTH_GOOGLE_ID` / `AUTH_GOOGLE_SECRET`.

## Production secrets

On Render, set these as environment variables on the **`trustmcp-web`** service
(`AUTH_SECRET` is generated by the Blueprint and `AUTH_URL` is preset to your domain):

```
AUTH_GITHUB_ID       <...>
AUTH_GITHUB_SECRET   <...>
AUTH_GOOGLE_ID       <...>
AUTH_GOOGLE_SECRET   <...>
```

(See `render.yaml` — these are declared as `sync: false` so you fill them in the
dashboard. See `DEPLOY.md` for the full flow.)

## Enterprise SSO (OIDC and SAML)

A generic **OIDC** provider is built in — set `SSO_ISSUER`, `SSO_CLIENT_ID`,
`SSO_CLIENT_SECRET` (and optional `SSO_NAME`). This covers Okta, Microsoft Entra ID,
Auth0, Google Workspace, and any OIDC IdP. Callback URL:
`https://<app>/api/auth/callback/sso`.

**SAML** IdPs are supported through a SAML→OIDC bridge so the app keeps a single, simple
OIDC integration:

- Most IdPs (Okta, Entra ID, Auth0, OneLogin) expose **both** SAML and OIDC apps — use
  the OIDC app and the built-in provider above.
- For SAML-only IdPs, run an open-source bridge such as **BoxyHQ SAML Jackson** (self-host
  or SaaS). Point `SSO_ISSUER`/`SSO_CLIENT_ID`/`SSO_CLIENT_SECRET` at Jackson's OAuth/OIDC
  endpoints; Jackson terminates SAML and presents OIDC to TrustMCP. Upload the IdP metadata to
  Jackson and you're done.

This keeps the app's auth surface to one well-tested protocol while still onboarding SAML
enterprises.

## Database migrations

The schema lives in `apps/web/prisma/schema.prisma` with a checked-in initial
migration under `apps/web/prisma/migrations/`. The web container runs
`prisma migrate deploy` at boot (see `apps/web/docker-entrypoint.sh`), so deploying a
new image applies pending migrations automatically. Locally:

```bash
pnpm --filter @trustmcp/web exec prisma migrate dev    # create + apply during development
pnpm --filter @trustmcp/web exec prisma migrate deploy # apply in CI/prod
```
